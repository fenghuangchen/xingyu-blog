> 记忆不是把所有事都存下来，而是知道此刻该想起什么。

过去半年，我给几个 Agent 项目加过「长期记忆」。最初的做法几乎一模一样：切块、嵌入、写入向量库，需要时按相似度捞回前 k 条。它在 Demo 里看起来很好，直到对话超过二十轮，直到用户问出那句——

**「你还记得我上次说过，我不喜欢被追问吗？」**

## 向量检索擅长什么

先把话说清楚：向量检索并没有错，它只是被用在了不该独自承担的位置上。

- **语义召回**：用户换了说法，仍然能找到相关内容；
- **模糊匹配**：不需要精确关键词，适合自然语言；
- **低成本扩展**：新内容写进去就能被检索。

问题在于，它只回答「哪段文本和现在最像」，却不回答另外三个更重要的问题：

1. 这件事现在还有效吗？
2. 它应该影响多久？
3. 什么时候应该主动忘记？

## 三层记忆，而不是一个池子

我后来把记忆拆成了三层，灵感来自认知科学里对工作记忆、情景记忆与语义记忆的划分。

| 层级 | 存什么 | 生命周期 | 实现 |
| --- | --- | --- | --- |
| 工作记忆 | 当前任务、最近几轮对话 | 分钟级 | 上下文窗口 |
| 情景记忆 | 某次对话里发生的事 | 天到周 | 摘要 + 时间戳 |
| 语义记忆 | 稳定的事实与偏好 | 长期 | 结构化条目 |

关键不是分层本身，而是**层与层之间有升降级**：一次对话里的偏好，被重复确认三次后，才允许进入语义记忆。

```ts
type Memory = {
  id: string;
  layer: "working" | "episodic" | "semantic";
  content: string;
  confidence: number;
  lastSeen: string;
  ttlDays: number;
};

function shouldPromote(memory: Memory) {
  return memory.layer === "episodic" && memory.confidence >= 0.75;
}
```

上面这段代码很朴素，却解决了我最头疼的问题：记忆开始有「重量」了。不是每条闲聊都值得被永久保存。

### 遗忘也是功能

我们总把遗忘当成缺陷，但在真实对话里，遗忘是一种礼貌。

> 一个记得你三年前随口一句抱怨的助手，不会让人觉得贴心，只会让人觉得被监视。

所以我会给情景记忆设置 TTL，并在用户明确说「忘掉这件事」时执行硬删除。删除接口必须是真的删除，而不是把 `deleted = 1` 写进表里然后继续参与检索。

## 我现在的判断标准

给记忆系统做评估时，我不再只看召回率，而是看四件事：

1. **相关性**：召回的内容是否真的和当前任务有关；
2. **时效性**：过期信息有没有被降权；
3. **可解释性**：能不能说清楚「我为什么记得这个」；
4. **可删除性**：用户要求忘记时，能否彻底移除。

## 写在最后

Agent 的记忆不该是一只越装越满的袋子。它更像一张会自己整理的书桌：常用的放在手边，过期的收进抽屉，不再需要的，就体面地丢掉。

下次再有人问我「怎么给 Agent 加记忆」，我大概会先反问一句：**你希望它记住什么，又希望它忘记什么？**
